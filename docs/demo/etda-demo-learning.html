1 แอปนี้คืออะไร?

Digital Wallet ฝั่ง Holder (ผู้ถือเอกสาร) — รับ VC จาก Issuer เก็บในเครื่องเข้ารหัส แล้วแสดงให้ Verifier เมื่อยินยอม

3 เรื่องหลักที่แอปทำ

เรื่อง มาตรฐาน ความหมายง่ายๆ
รับเอกสาร OID4VCI 1.0 ขอ VC จาก ThaID / ใบขับขี่ / Transcript แล้วเก็บในเครื่อง
แสดงออนไลน์ OID4VP 1.0 สแกน QR Verifier หรือ My QR → ส่งเฉพาะข้อมูลที่เลือก
แสดงใกล้ตัว (NFC) ISO 18013-5 แตะเครื่องอ่าน NFC — ยังไม่ demo

เอกสาร 3 ชนิด

  • Thai National ID (ThaID / PID) — ต้องมีก่อน ถึงจะขอเอกสารอื่นได้
  • DLT Driving Licence — ต้องมี ThaID ก่อน
  • Chulalongkorn Transcript — ต้องมี ThaID ก่อน

3 Flow หลัก 3 แบบ

เข้าใจ 3 flow นี้ = พร้อม demo 80%

Flow A — รับเอกสารผ่าน Portal (OID4VCI)

Wallet Home → กด "ขอเอกสาร" → เปิด browser Issuer (/thaiid/login) → login + verify ตัวตน (DL/Transcript ทำบนเว็บ Issuer) → redirect: walletapp://callback?credential_offer_uri=https://... → แอป parse → หน้ารับเอกสาร → biometric (sign PoP) → บันทึก VC เข้า MMKV เข้ารหัส → การ์ดเอกสารโผล่หน้า Wallet

ThaID ผ่านแล้ว Issuer ต้อง whitelist walletapp://callback

Flow B — แสดงเอกสาร Scan tab (OID4VP)

Scan tab → สแกน QR Verifier (openid4vp://...) → ตรวจ trust Verifier (allowlist) → หน้า Consent → Info (เลือก claim ที่จะเปิด) → กดยอมรับ → biometric (sign KB-JWT) → direct_post ไป Verifier → Success + บันทึก History

ผ่านแล้ว Verifier เริ่ม flow นี้

Flow C — My QR (Wallet เริ่มก่อน)

My QR tab → POST /broker/session → แสดง QR → Verifier สแกน QR → POST /verifier/scan → Verifier deposit OID4VP request กลับ Broker → Wallet poll GET .../request (ทุก 2 วิ) → flow ยินยอม/sign เหมือน Scan tab → direct_post → Success

ยังขาด E2E ต้องประสาน Verifier scan + deposit request

4 My QR — วิธีทดและแก้ปัญหา

Golden path ที่ยังขาด — ทำให้ผ่านก่อน demo

Checklist ฝั่ง Wallet

  1. มี ThaID แบบ SD-JWT ใน wallet (presentable)
  2. Build มี EXPO_PUBLIC_BROKER_BASE_URL ชี้ Broker ที่ถูก
  3. เปิด My QR → เห็น QR + countdown (~5 นาที)

Checklist ฝั่ง Verifier (ประสานทีม)

  1. Scan QR แล้วเรียก POST /verifier/scan
  2. Body: { "scannedValue": "<qr_payload verbatim>", "docType": "IDCard" }
  3. Deposit OID4VP request กลับ Broker ภายใน TTL

ถ้า My QR ไม่ทำงาน

Broker POST /broker/session ล้ม — เช็ค SSL pin, URL, backend online. ดู log tag [vp-broker] session-start-failed
Verifier ยังไม่ scan หรือยังไม่ deposit request กลับ Broker. Wallet poll ทุก 2 วิ — รอให้ Verifier ทำครบ
ThaID ไม่ใช่ SD-JWT หรือ status ไม่ presentable — ต้อง reissue หรือ renew

5 P-256 / ES256 — กุญแจใหม่ก่อน Demo

Spec: docs/superpowers/specs/2026-08-04-hardware-p256-es256-signing-design.md

เปลี่ยนจากอะไร → อะไร

Private key ใน JSมีตอน signไม่มี — sign ผ่าน native
Holder DIDdid:key Ed25519did:key P-256

ทำไมเปลี่ยน?

  • Galaxy ไม่รองรับ Ed25519 ใน Keystore → เลยใช้ software seed (ไม่ ideal)
  • Stakeholder ยอมรับ P-256 / ES256 แล้ว → กลับไป hardware non-extractable ได้
  • StrongBox รองรับ P-256 เป็น baseline

กฎสำคัญ

  • StrongBox ก่อน → ถ้าไม่มีค่อย TEE → ไม่มี software fallback
  • Biometric ครั้งเดียว ต่อ action (action-scoped signing session)
  • Fresh reissue — credential เก่า sign ไม่ได้ ต้องขอใหม่จาก Issuer
  • iOS production blocked จนกว่าจะมี Secure Enclave
พูดกับ ETDA (1 นาที) "กุญแจ P-256 เก็บใน Android Keystore ไม่ extract ได้ — ลอง StrongBox ก่อน ลงนาม ES256 ทุกจุดที่ wallet sign — demo ใช้ build ที่ migrate แล้ว credential ออกใหม่บน hardware key"

6 StrongBox vs TEE — ต่างกันยังไง?

ทั้งคู่อยู่ใน Android Keystore — private key ไม่ออกมาในแอป

🔒 StrongBox

  • ชิปความปลอดภัย แยก จาก CPU หลัก
  • ความปลอดภัย สูงสุด — ทน physical attack
  • ช้ากว่า, จำกัดจำนวน key
  • Galaxy A26 (Knox Vault) — น่าจะมี
  • Flagship, Pixel 3+, Samsung S21+

🛡️ TEE

  • โซนปลอดภัย ในชิป หลัก (TrustZone)
  • ความปลอดภัย ดี — ยัง hardware-backed
  • เร็วกว่า, รองรับ key มากกว่า
  • Mid-range หลายรุ่น (A15, A35 ไม่มี StrongBox แต่มี TEE)
  • Fallback เมื่อ StrongBox ไม่มี

แอปเราเลือกยังไง?

สร้าง key ครั้งแรก: 1. ลอง StrongBox (P-256) 2. StrongBoxUnavailableException → สร้างใน TEE 3. TEE ก็ไม่ได้ → fail closed (ไม่ใช้ software key) ตอน sign: → ใช้ key เดิมเท่านั้น — ไม่สร้าง key ใหม่แอบๆ

มือถือไหนมักไม่มี StrongBox?

  • Budget / entry (Redmi A, realme C, Samsung A0x/A1x บางรุ่น)
  • Mid-range หลายรุ่น — ยืนยันแล้ว: Galaxy A15, A35
  • Android 8 ลงไป — ไม่มี StrongBox API

ไม่มี list ครบ เช็คบนเครื่อง: PackageManager.FEATURE_STRONGBOX_KEYSTORE

ไม่มี StrongBox ≠ ใช้แอpไม่ได้ — ยังใช้ TEE ได้ (security ต่ำกว่า StrongBox แต่ยัง hardware-backed)

8 คำถามที่ ETDA มักถาม

Build demo = ES256 / P-256 hardware ใน Android Keystore. ไม่ใช้ Ed25519 software อีกต่อไปหลัง cutover.
P-256 ใน Keystore (StrongBox หรือ TEE) — private key ไม่ออกมาในแอป. Biometric ทุกครั้งที่ sign. WP remote attestation verify hardware backing.
ขอ credential จาก Issuer ตรงบนเครื่อง (OID4VCI). Backend sync เป็น optional หลัง save local.
ThaID = PID (เอกสารหลักยืนยันตัวตน). ใบขับขี่และ Transcript ต้อง verify ผ่าน PID ก่อน — logic ใน credentialGuard.
ครั้งเดียว ตอน sign — action-scoped session. ไม่ prompt ซ้ำหน้า consent.
StrongBox = ชิปแยก (แข็งแกร่งกว่า). TEE = โซนในชิปหลัก (fallback). ไม่มี StrongBox ยังใช้แอpได้ถ้ามี TEE.
