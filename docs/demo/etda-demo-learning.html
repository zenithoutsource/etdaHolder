Digital Wallet — Holder

เรียนรู้ว่าแอป Wallet ทำอะไร flow การรับและแสดงเอกสาร Orval SDK และความปลอดภัย P-256 / StrongBox ทำงานอย่างไร

สารบัญ
ภาพรวมแอป Orval SDK Flow หลัก My QR P-256 / ES256 StrongBox vs TEE คำถามที่พบบ่อย

1 แอปนี้คืออะไร?

Digital Wallet ฝั่ง Holder (ผู้ถือเอกสาร) — รับ Verifiable Credential จาก Issuer เก็บในเครื่องเข้ารหัส แล้วแสดงให้ Verifier เมื่อผู้ใช้ยินยอม

3 เรื่องหลักที่แอปทำ

เรื่อง มาตรฐาน ความหมาย
รับเอกสาร OID4VCI 1.0 ขอ VC จาก Issuer (ThaID, ใบขับขี่, Transcript) แล้วเก็บในเครื่อง
แสดงออนไลน์ OID4VP 1.0 สแกน QR ของ Verifier หรือใช้ My QR → ส่งเฉพาะข้อมูลที่เลือก
แสดงใกล้ตัว ISO 18013-5 แตะเครื่องอ่าน NFC (mdoc proximity) — กำลังพัฒนา

เอกสารที่รองรับ

  • Thai National ID (ThaID / PID) — เอกสารหลัก ต้องมีก่อนขอเอกสารอื่น
  • DLT Driving Licence — ต้องมี ThaID ที่ใช้งานได้ก่อน
  • Chulalongkorn Transcript — ต้องมี ThaID ที่ใช้งานได้ก่อน

แท็บในแอป

Walletหน้าแรก — ดูการ์ดเอกสาร, ขอเอกสารจาก Issuer portal
My QRHolder แสดง QR — Verifier มาสแกนแล้วขอข้อมูล
Scanสแกน QR รับเอกสาร (OID4VCI) หรือแสดงให้ Verifier (OID4VP)
History Logประวัติการรับและแสดงเอกสาร

สองทางสื่อสารของแอป

Issuer (หน่วยออกเอกสาร)

  • OID4VCI — รับ VC ตรงบนมือถือ
  • ไม่ผ่าน Wallet Backend บริษัท
  • เก็บใน MMKV เข้ารหัส

Wallet Backend (บริษัท)

  • Login, บัญชี, sync credential (optional)
  • ผ่าน Orval SDK
  • แยกจาก protocol Issuer

2 Orval SDK คืออะไร?

โค้ดที่ generate อัตโนมัติสำหรับเรียก API ของ Wallet Backend — ไม่เกี่ยวกับการขอเอกสารจาก Issuer

สรุป Orval อ่านสเปก API (walletApi.json) แล้วสร้าง TypeScript ใน src/sdk/walletApi.ts — แอป เรียกฟังก์ชันเช่น loginUser() แทนการเขียน HTTP เองทีละ endpoint

เปรียบเทียบ

ไม่มี SDKOrval SDK
อ่านเอกสาร API เองเรียกฟังก์ชันที่ generate แล้ว
เขียน URL/body เอง — พิมพ์ผิดได้TypeScript ช่วยตรวจ type
API เปลี่ยน → แก้หลายจุดyarn sdk:generate แล้วแก้ตาม type error

ขั้นตอนในโปรเจกต์

walletApi.json ↓ yarn sdk:generate (Orval — รันตอน develop) src/sdk/walletApi.ts (ห้ามแก้มือ) ↓ แอป เรียก login, register, importCredential ฯลฯ

ฟังก์ชันที่ mobile ใช้ (ตัวอย่าง)

ฟังก์ชันหน้าที่
loginUserเข้าสู่ระบบ Wallet Backend
registerUserสมัครบัญชี
getWalletsดูรายการ wallet ของ user
importCredentialsync VC ที่เก็บในเครื่องไป backend (optional)

หมายเหตุ OID4VCI (ขอ VC จาก Issuer) รันบน device ผ่าน @sphereon/oid4vci-client — ไม่ผ่าน Orval SDK

3 Flow หลัก

เส้นทางที่ผู้ใช้และระบบทำงานร่วมกัน

รับเอกสาร — Portal + OID4VCI

Wallet Home → ขอเอกสาร → เปิด browser Issuer (/thaiid/login) → login (DL/Transcript: verify PID บนเว็บ Issuer) → redirect: walletapp://callback?credential_offer_uri=https://... → แอป parse offer → token → proof (sign) → รับ VC → บันทึก MMKV เข้ารหัส → แสดงการ์ดบน Wallet

Issuer ต้อง redirect เป็น walletapp://callback?credential_offer_uri=... (HTTPS offer URL)

แสดงเอกสาร — Scan tab (OID4VP)

Scan → สแกน openid4vp://... → ตรวจ trusted Verifier → Consent → Info (เลือก claim) → ยอมรับ → sign (biometric) → direct_post ไป Verifier → บันทึก History

แสดงเอกสาร — My QR (Wallet เริ่มก่อน)

My QR → POST /broker/session → แสดง qr_payload → Verifier สแกน → POST /verifier/scan → Verifier deposit OID4VP request ที่ Broker → Wallet poll GET .../request → flow ยินยอม/sign เหมือน Scan tab → direct_post

Scan vs My QR

ScanMy QR
ใครเริ่มVerifier แสดง QRHolder แสดง QR
ช่องทางกลางไม่มีWallet Broker
หลังได้ requestUI และการ sign เหมือนกัน

4 My QR ทำงานอย่างไร

Holder เปิด QR → Broker เป็นตัวกลางรอ Verifier → ได้ OID4VP request แล้วเข้า flow แสดงเอกสารปกติ

บทบาทแต่ละฝ่าย

ฝ่ายทำอะไร
WalletPOST /broker/session → แสดง QR → poll request
Brokerเก็บ session, รับ request จาก Verifier, ให้ Wallet ดึง
Verifierสแกน QR → POST /verifier/scan → deposit OID4VP request

เอกสารที่ใช้แสดง

แอป เลือก credential อัตโนมัติ: ใบขับขี่ dual-format (ถ้าพร้อม) หรือ ThaID SD-JWT ที่ presentable

รายละเอียด API (Verifier scan)

POST /verifier/scan { "scannedValue": "<qr_payload จาก QR verbatim>", "docType": "IDCard" }

Wallet poll GET /broker/session/{id}/request ทุก 2 วินาที จนได้ authorization request

5 P-256 / ES256 (การลงนาม)

แผน production: hardware P-256 ใน Android Keystore — spec 2026-08-04-hardware-p256-es256-signing-design.md

ทิศทางการเปลี่ยน

หัวข้อแนวทาง production
CurveP-256 (secp256r1) ใน Keystore
JWT algorithmES256
Private keyอยู่ใน hardware — JavaScript ไม่เห็น
Holder DIDdid:key แบบ P-256
ใช้ signPoP (รับ VC), KB-JWT (แสดง VC), attestation, mdoc proximity

เหตุผล

  • Android Keystore รองรับ P-256 ใน StrongBox/TEE ได้ดี
  • Ed25519 ใน Keystore ไม่ reliable บนอุปกรณ์เป้าหมาย → เคย fallback เป็น software seed
  • Stakeholder ยอมรับ ES256 สำหรับ holder proofs → กลับไป hardware-backed ได้

กฎสำคัญ

  • StrongBox ก่อน → TEE เมื่อ StrongBox ไม่มี → ไม่มี software fallback
  • Biometric ครั้งเดียวต่อ user action (action-scoped signing session)
  • เปลี่ยน algorithm ต้อง reissue credential ใหม่จาก Issuer
  • iOS production รอ Secure Enclave slice

6 StrongBox vs TEE

ทั้งคู่เป็น Android Keystore — private key ไม่ออกมาในแอป

StrongBox

  • ชิปความปลอดภัยแยกจาก CPU
  • ความปลอดภัยสูงสุด — ทน tampering
  • ช้ากว่า, จำกัดจำนวน key
  • ม частоใน flagship / Knox Vault (เช่น Galaxy A26 คาดว่ามี)

TEE

  • โซนปลอดภัยในชิปหลัก (TrustZone)
  • hardware-backed — ดีกว่า software key
  • เร็วกว่า, รองรับ key มากกว่า
  • Fallback เมื่อไม่มี StrongBox (เช่น Galaxy A15, A35)

นโยบายในแอป

createKey: 1. ลอง StrongBox (P-256) 2. StrongBoxUnavailableException → สร้างใน TEE 3. TEE ไม่ได้ → fail closed sign: ใช้ key เดิมเท่านั้น — ไม่สร้าง key ใหม่เมื่อ sign ล้ม

ไม่มี StrongBox ไม่ได้หมายความว่าใช้แอปไม่ได้ — ยังใช้ TEE ได้ถ้ามี hardware-backed keystore

7 คำถามที่พบบ่อย

OID4VCI = ขอ VC จาก Issuer บนมือถือ (Sphereon client). Orval SDK = เรียก Wallet Backend บริษัท (login, sync) — คนละระบบ
ไม่โดยอัตโนมัติ — รับและเก็บ local ก่อน. Sync ไป backend เป็น optional ผ่าน importCredential
ThaID เป็น PID (เอกสารยืนยันตัวตนหลัก). ใบขับขี่และ Transcript ต้อง verify ผ่าน PID ก่อน — ตรวจใน credentialGuard
ครั้งเดียวต่อ action ที่ต้อง sign — ผ่าน action-scoped signing session ไม่ prompt ซ้ำหน้า consent
Encrypted MMKV บน device — กุญแจเข้ารหัสอยู่ใน Keychain/Keystore. ไม่ใช้ AsyncStorage
StrongBox = ชิปแยก (แข็งแกร่งกว่า). TEE = โซนในชิปหลัก. แอป ลอง StrongBox ก่อน แล้ว fallback TEE ถ้าไม่มี
