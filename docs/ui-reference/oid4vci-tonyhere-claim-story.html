FAILURE LADDER // 7 — ROOT CAUSE

PoP: jwk + kid พร้อมกัน = 400

Spec: proof JWT header เลือก หนึ่งใน kid | jwk | x5c. Procivis OpenID4VCIProofJWTFormatter::verify_proof fail ชัดเจนเมื่อมีทั้งคู่ แล้ว map เป็น InvalidOrMissingProof (ชื่อ error กว้าง — มี proof ก็ได้ 400)

BROKEN header
{ "alg": "ES256", "typ": "openid4vci-proof+jwt", "jwk": { "kty":"EC", "crv":"P-256", … }, "kid": "did:key:zDnae…#zDnae…" }
FIXED header (keyBinding: jwk)
{ "alg": "ES256", "typ": "openid4vci-proof+jwt", "jwk": { "kty":"EC", "crv":"P-256", … } } # ไม่มี kid # payload: { aud, iat, nonce }
Fix ใน src/services/crypto/hardwareJwtSigner.ts → signHardwareProofJwt · อัปเดต assert ใน exchangeService.ts ให้ mso_mdoc ไม่บังคับ kid อีกต่อไป · did-kid path ยังส่ง kid อย่างเดียวตามเดิม

CHECKLIST

เมื่อเจอ path-based issuer อีก — ไล่ตามนี้

1. Identity ของ session

  • อ่าน credential_issuer จาก offer
  • เทียบกับ origin CI metadata / AS insert (RFC 8414)
  • ยืนยัน token/credential/nonce URL เป็น session ไม่ใช่ origin-root

2. Token body

  • ดู AS token_endpoint_auth_methods_supported
  • anonymous → อย่าใส่ client_id/resource
  • attestation เฉพาะตอนถูก advertise

3. Proof material

  • มี c_nonce จาก token หรือ nonce endpoint?
  • header มี อย่างใดอย่างหนึ่ง ของ kid|jwk|x5c?
  • aud = credential_issuer ของ offer?

4. Config id

  • offer id อยู่ใน credential_configurations_supported?
  • ถ้าไม่ — overlay/synthesize ก่อน retrieve
  • wire ยังส่ง offered id (OID4VCI 1.0)
Production: ปิด TRUST_ANY_OID4VC_PEER · คง fail-closed (verify alg, cnf binding, pinning, no cross-host metadata)
